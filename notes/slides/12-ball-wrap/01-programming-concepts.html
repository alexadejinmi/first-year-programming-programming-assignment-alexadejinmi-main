12 — Wrapping Around the Edges

Programming concepts

Screen-wrap ("Pac-Man" edge) behaviour

Instead of drifting off the canvas forever, a ball that reaches one edge should reappear at the opposite edge — the way movement wraps around in games like Pac-Man. This is a small, specific kind of boundary behaviour: nothing about the ball's velocity changes, only its position gets folded back into the visible canvas whenever it would otherwise leave it.

The modulo operator %

this.x = (this.x + this.vx + width) % width;

% (modulo) gives the remainder after dividing the left value by the right one — 7 % 3 is 1, since 3 goes into 7 twice with 1 left over. Applied to a position and a boundary, value % limit always produces a result between 0 and limit - 1 (or -1, in most other languages that allow negative results — this pattern's extra + width exists specifically to keep the result positive), regardless of how far past the boundary value was. That's exactly screen-wrap: whatever this.x + this.vx comes out to, taking it % width folds it back into the range 0 to width - 1.
