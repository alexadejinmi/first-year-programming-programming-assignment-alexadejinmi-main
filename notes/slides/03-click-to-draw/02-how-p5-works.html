03 — Click to Draw

How p5 works

  • Event callback functions. mousePressed() and keyPressed() are, like setup() and draw(), functions that p5 calls for you — you never call them yourself. But unlike setup()/draw(), p5 doesn't call them on a schedule: it calls mousePressed() exactly when the mouse button goes down, and keyPressed() exactly when a key goes down, each time that real event happens in the browser. Give a function one of these exact names and p5 automatically wires it up to the matching event — nothing else needs to change.
  • draw() keeps running in the background regardless. Even though draw() is empty here, p5 is still calling it ~60 times a second, same as sketch 02 — the render loop never stops on its own. It simply has nothing to do, so nothing changes on screen between clicks.
  • The canvas keeps accumulating marks. background() is no longer called inside draw(), so nothing erases previous frames automatically. Because the canvas is a persistent bitmap (from sketch 01), every circle drawn by mousePressed() stays exactly where it was drawn, and clicks build up a picture rather than replacing it — until keyPressed() explicitly paints over everything with background(230).
