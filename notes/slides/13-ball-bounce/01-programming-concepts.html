13 — Ball Bounce

Programming concepts

Boolean expressions and comparisons

this.x + radius > width

An expression like this one doesn't produce a number — it produces one of exactly two values, true or false, depending on whether the comparison holds. Values of this kind are called booleans. > (greater than) is a comparison operator; others include < (less than), >=/<= (greater/less than or equal to), === (equal to) and !== (not equal to). Every condition an if checks is a boolean expression like this one.

Branching: if / else if

A generic example, unrelated to balls — grading a score:

if (score >= 90) {
    console.log("A");
} else if (score >= 80) {
    console.log("B");
} else if (score >= 70) {
    console.log("C");
} else {
    console.log("F");
}

if runs its block only when its condition is true; otherwise it skips straight past it. else if attaches an alternative condition, checked only if every earlier condition in the chain was false. Only one block in the whole chain ever runs — as soon as one condition is true, its block runs and every later else if/else in that chain is skipped, even if their conditions would also have been true. With score at 85, only "B" prints, even though score >= 70 is also true — the chain never reaches it. An optional final else (no condition) catches everything not matched by any branch above it.

Sketch 13's chains have no final else — if none of the conditions are true, nothing in that chain runs at all, which is exactly right here: a ball that hasn't touched an edge needs no correction.

Collision detection against a boundary

"Has this ball touched the edge of the canvas?" becomes a boolean comparison between the ball's position and the canvas edge: this.x + radius > width is true exactly when the ball's right edge has gone past the canvas's right edge. Checking a moving object's position against a boundary like this, every frame, is the general idea behind collision detection — used here against the canvas edge, and reused (against other balls, then against rectangles) in the exercises below.

Reflecting velocity: negation

this.vx *= -1;

Multiplying a number by -1 flips its sign — a positive velocity becomes negative and vice versa. Since vx/vy control direction as well as speed (from sketch 11), flipping their sign is exactly what makes a ball bounce: same speed, opposite direction.

Correcting position while reacting to a collision

} else if (this.x + radius > width) {
    this.x = width - radius;
    this.vx *= -1;
}

Two things happen together on a collision: the velocity is reflected (so the ball starts moving the other way), and the position is clamped — snapped back to exactly touch the edge (width - radius), not left wherever it happened to land. Without the clamp, a fast-moving ball could end up drawn partly off-canvas for one frame before bouncing back.

Edge case handling

if (this.diameter > width) {
    this.x = width / 2;
    this.vx = 0;
}

A ball wider than the canvas itself breaks the ordinary bounce logic — it could never simultaneously satisfy "left edge inside the canvas" and "right edge inside the canvas". This extra branch is edge case handling: a special situation that the general-purpose logic doesn't cover correctly, checked and handled separately, before the general case runs.
