01 — Drawing a Circle

Programming concepts

A program is a list of instructions

A computer program is a sequence of statements — small instructions, carried out one after another, top to bottom. In JavaScript most statements end with a semicolon ;, the same way a sentence ends with a full stop:

createCanvas(640, 360);
background(230);

These are two separate instructions: "create a canvas", then "paint the background".

Calling a function

createCanvas(640, 360) is a function call. A function is a named, ready-made piece of behaviour — someone else already wrote the instructions for "create a canvas" and gave that block of instructions the name createCanvas. To use it, write its name followed by parentheses: createCanvas(...). This is called calling (or invoking) the function.

Everything used in this sketch — createCanvas, background, noStroke, fill, circle — is a function call. None of these functions are defined anywhere in this file; they're built into the p5 library, which the sketch loads automatically (see index.html). Students will start writing their own functions in sketch 07 — for now, just recognise the shape name(...) as "run this ready-made behaviour".

Arguments

The values inside the parentheses are arguments — the information a function needs to do its job. circle(320, 180, 150) passes three arguments: an x position, a y position, and a diameter. Two things matter about arguments:

  • Order matters. Swapping the first two arguments to circle() would move the circle, not resize it — each position in the list means something specific, fixed by however the function was written.
  • Different functions expect different arguments. fill(255, 0, 100, 150) takes four numbers (red, green, blue, opacity), background(230) takes one (a single grey value), circle(320, 180, 150) takes three (x, y, diameter). There's no way to guess what a function's arguments mean just from looking at a call — that's what documentation (the p5 reference) is for.

JavaScript is case-sensitive

Every name in this sketch — createCanvas, background, noStroke, fill, circle, setup, draw — has to be typed with exactly the right mix of upper- and lower-case letters. createCanvas is not the same name as createcanvas or CreateCanvas; JavaScript (and p5's own functions, which are just JavaScript) treats those as three completely different, unrelated names, and only one of them actually exists. Get the case wrong and the result isn't a slightly-wrong circle — it's an error, because as far as JavaScript is concerned the function you typed was never defined at all. Worth knowing now, before sketch 04 has students typing their own names for the first time: a typo in case is exactly as broken as a typo in spelling, even though it can look right at a glance.

Code blocks and function declarations

function setup() {
    ...
}

This is different from the function calls above — it's a function declaration, not a call. The keyword function, a name (setup), parentheses, and then a pair of curly braces { } containing statements. The braces mark a block — a group of statements that belong together and run as a unit. Everything between setup()'s { and } is what happens when setup runs. setup and draw are declared for us in this sketch's skeleton; students aren't writing their own function declarations yet — that starts in sketch 07 — but recognising the shape now (a name, then a block of statements it owns) makes every later sketch easier to scan.

Hard-coded ("magic") numbers

Every argument in this sketch is a literal number typed directly into the call: 640, 360, 230, 320, 180, 150. These are sometimes called magic numbers — values with no name attached to explain what they mean or why they were chosen. 150 appears twice in this sketch, meaning two completely different things (a diameter, and an alpha/opacity value) purely by coincidence. Nothing is wrong with this yet — it's the natural starting point — but it's worth noting as something to watch for: sketch 04 replaces these literals with named variables, which makes the code easier to read and to change.

Comments

// What changed: draws a single circle once, using hard-coded numbers.

Text after // is a comment — a note for human readers that JavaScript ignores completely. Comments don't affect what the program does; they exist purely to explain why, not what (the code itself already says what).
