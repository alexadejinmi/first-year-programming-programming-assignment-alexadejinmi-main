01 — Drawing a Circle

How p5 works

p5.js is a JavaScript library for drawing and animation. It works differently from a plain script that just runs top to bottom once — understanding its execution model is the single most important thing for being able to read a sketch and predict what it will do before running it.

  • p5 calls your functions for you. Loading the sketch doesn't run setup() or draw() directly — it defines them. p5 itself decides when to call them, by name. You never write setup(); anywhere; p5 finds the function you named setup and calls it for you.
  • The lifecycle has two parts. p5 calls setup() exactly once, when the sketch starts. Then it calls draw() automatically and repeatedly — by default about 60 times a second — for as long as the sketch keeps running. In this sketch draw() is empty, so nothing visible happens after setup() finishes, but p5 is still calling it, 60 times a second, doing nothing. (Later sketches make good use of this repeated calling — that's how animation happens.)
  • createCanvas(width, height) creates the rectangular drawing surface the sketch draws onto, and also sets two system variables, width and height, that the rest of the sketch can read later (used from sketch 12 onwards).
  • The coordinate system: (0, 0) is the top-left corner of the canvas. x increases moving right, y increases moving down the screen — the opposite of a maths graph, where y increases upward. circle(320, 180, 150) is centred 320 pixels from the left and 180 pixels down from the top.
  • The canvas is a persistent bitmap, not a picture that redraws itself from a description. Whatever is drawn stays exactly where it is, pixel for pixel, until something else draws over it. background(230) works by painting the entire canvas a flat grey — it's not a special "clear" operation, just an ordinary drawing call that happens to cover everything. This matters from sketch 02 onwards, where background() has to be called every frame to stop old frames piling up.
  • Style calls vs. drawing calls. noStroke() and fill(255, 0, 100, 150) don't draw anything themselves — they set state: "don't outline shapes" and "fill shapes with this colour", respectively. That state applies to whatever is drawn after it. circle(320, 180, 150) is the actual drawing call — it's the one line in this sketch that puts something on screen, and it uses whatever fill/stroke state was set before it ran. Order matters: calling fill() after circle() would have no visible effect on that circle.
