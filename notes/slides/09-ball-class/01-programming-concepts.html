09 — A Ball Class

Programming concepts

Classes: class and constructor

class Ball {
    constructor(x, y, d, c) {
        this.x = x;
        this.y = y;
        this.diameter = d;
        this.col = c;
    }
    ...
}

A class is a template for creating objects that all share the same shape (the same properties) and the same behaviour (the same functions to act on them). constructor is a special function inside the class, called automatically whenever a new ball is created — it takes over the job createBall() used to do, assigning each parameter to a property.

this

Inside a class, this refers to the particular object currently being built or acted on — this.x = x; means "set the x property of this ball to the parameter x". Every ball gets its own x, y, diameter, col, even though they're all built from the same constructor code — this is what makes each one refer to its own copy rather than some shared one.

Methods vs. plain functions

display() {
    noStroke();
    fill(this.col);
    circle(this.x, this.y, this.diameter);
}

A function declared inside a class, like display(), is called a method. Calling it looks like ball.display() rather than displayBall(ball) — the object comes first, and this inside the method automatically refers to whichever ball it was called on. display() takes over the job displayBall() did in sketch 08, but reads this.col/this.x/... instead of a parameter, since the object it's acting on is always this, never something passed in explicitly.

new — creating an instance

ball = new Ball(320, 180, 150, col);

new creates an instance of a class — an actual object built from that template, with the constructor's parameters supplied as arguments, exactly like calling createBall(...) did before. ball now holds one Ball instance instead of a plain object literal.

Object-oriented programming

Sketches 06–08 kept a ball's data (the object literal) and the behaviour that acts on it (createBall(), displayBall()) as separate things, only related by convention — nothing enforced that displayBall() was ever used with a ball-shaped object. A class bundles both together into one type: Ball is both the data it holds and the methods that act on it. This general approach — organising code around types that bundle data with the behaviour that operates on it — is called object-oriented programming.

Why classes exist at all — and when they don't: a class earns its keep when a sketch needs several instances of the same kind of thing, each with its own copy of the same data and the same behaviour — that's exactly the sketch 10 situation coming next, five separate Balls all built from one template. Rule of thumb: reach for a class when you need multiple objects that all share a shape and a set of operations. A single one-off object doesn't need a class at all — sketch 06's lone ball object literal is simpler as-is, and turning it into a class there would have been machinery with nothing to justify it; the same is true any time there's only ever going to be one of something.
