06 — A Ball Object

Programming concepts

Object literal syntax

ball = {
    x: 320,
    y: 180,
    diameter: 150,
    col: col
};

Sketch 05's col was an object p5 built for us. ball is the first object written by hand in the series — an object literal: curly braces containing key: value pairs, separated by commas. Each key names one property; ball bundles x, y, diameter and col — everything that used to be four separate global variables — into one object.

Dot notation

ball.x = mouseX;
ball.y = mouseY;
...
fill(ball.col);
circle(ball.x, ball.y, ball.diameter);

A property inside an object is read or written using dot notation: ball.x reads (or, on the left of =, writes) the x property of ball. This replaces what would otherwise be four separate variable names with one consistent pattern — ball. followed by whichever property is needed.

Local variables

function setup() {
    ...
    let col = color(255, 0, 100, 150);
    ball = { ..., col: col };
}

col here is declared inside setup(), with let — and it's the first local variable in the series. A local variable is created fresh each time its function runs, and no other function can see it — unlike the global bg/diameter from sketch 04, which any function in the sketch can read. setup() only ever runs once here, so the distinction isn't visible yet in this sketch's behaviour, but it matters as soon as a function with local variables of its own runs repeatedly — as move() will, from sketch 11 onward.

Why ball needs let, not const

ball reuses the same pattern col used in sketch 05: declared globally with no value (let ball;), then assigned inside setup(). The reason is the same too — its value (the object literal, which itself needs col) isn't available until setup() runs, so it can't be a const. This is the pattern's second appearance, not its first — it recurs through the rest of the sketches wherever a global depends on something only available once setup() starts.
