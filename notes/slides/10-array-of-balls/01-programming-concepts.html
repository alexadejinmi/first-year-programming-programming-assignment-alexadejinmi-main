10 — An Array of Balls

Programming concepts

Arrays — a list of values

balls = [
    new Ball(100, 100, 60,  color(255, 0, 100, 200)),
    new Ball(300, 150, 100, color(0, 200, 100, 180)),
    ...
];

An array is an ordered list of values, written between square brackets [ ] with commas between entries — an array literal, the same idea as the object literal from sketch 06 but for a list rather than a set of named properties. Any kind of value can go in an array; here each entry is a Ball object. Where every earlier sketch had one ball variable holding one object, balls is a single variable holding several — this is the direct answer to the awkwardness of needing ball2, ball3, ... that would otherwise creep in as more objects are needed.

Why arrays exist at all: separate numbered variables don't scale — they can't be looped over (there's no way to write "do this to ball1 through ball5" without naming each one), and changing how many balls exist means adding or removing variable names throughout the code. An array sidesteps both problems: any number of elements live under one name, and code that works on "the array" automatically works whether it holds 1 element or 100. Rule of thumb: reach for an array whenever there's a number of same-shaped things that could grow, shrink, or is simply too many to give each its own variable name — the moment you catch yourself about to write thing2, thing3, ..., that's an array.

Indexing — reading one element by position

balls[i]

Each element in an array has a numbered position, called its index, starting at 0 for the first element (not 1) — balls[0] is the first ball, balls[1] the second, and so on. Square-bracket notation after the array's name — balls[i] — reads (or, elsewhere, could assign) the element at that position. This is a different bracket use from the array literal above: [ ] after a value's name indexes into it, [ ] on its own builds an array.

array.length

i < balls.length

balls.length is a property (dot notation, from sketch 06) holding how many elements are currently in the array — 5 for this sketch's array. It's read, not written, and it stays in sync automatically as the array's contents change, which is what lets a loop work for an array of any size without editing the loop itself.

for loops

for (let i = 0; i < balls.length; i++) {
    balls[i].display();
    ...
}

A for loop repeats a block of statements, varying one counter each time round. This one has three parts, separated by semicolons, all on the same line:

  • let i = 0 — runs once, before the loop starts: create a counter variable i, starting at 0.
  • i < balls.length — checked before each repetition: keep looping only while this is true.
  • i++ — runs after each repetition: increase i by one (i++ is shorthand for i = i + 1).

So this loop runs its block once for i = 0, once for i = 1, and so on, stopping as soon as i reaches balls.length — which visits every valid index in the array exactly once, from the first element to the last, however many elements it holds.

Strings and concatenation

text("Ball " + i, balls[i].x, balls[i].y);

"Ball " is a string — text data, written between quotes. The + operator, used between a string and a number, concatenates (joins) them into one string, automatically converting the number to text first: with i equal to 2, "Ball " + i produces the string "Ball 2". This is how a label built from a loop counter gets its number.

Loop forms: for, while, for...of

A for loop is one way to repeat a block of code, but not the only way — the same repetition can be written differently. Take a generic example, unrelated to balls: printing every item in an array called items.

// for — the three loop parts are written together, on one line
for (let i = 0; i < items.length; i++) {
    console.log(items[i]);
}
// while — the same three parts, but spread out: before, as the condition, and last inside the block
let i = 0;
while (i < items.length) {
    console.log(items[i]);
    i++;
}

A while loop only checks a condition and repeats while it's true — it has no built-in counter, so the loop above has to create i before the loop and increase it manually, as the last line inside the block. Read the for loop's three parts against the while version: its let i = 0 is the line before the loop, its i < items.length is the while's condition, and its i++ is the last line inside the block. A for loop is really a while loop with those three parts collected into one place.

// for...of — no index at all: hands you each element directly
for (const item of items) {
    console.log(item);
}

for...of is a third form, for when the index itself isn't needed — it hands each element of the array to item directly, one at a time, with no counter to create or update. It's shorter whenever the code only needs the elements.

It becomes awkward the moment the code does need the index for something else (a position in a label, say) — for...of doesn't give you one automatically. Nothing stops you tracking one yourself, though: declare a counter before the loop and increase it by hand, the same way the while version above did.

// for...of, with a manually tracked index
let i = 0;
for (const item of items) {
    console.log(i, item);
    i++;
}
