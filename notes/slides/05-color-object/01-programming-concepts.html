05 — A Colour Object

Programming concepts

Objects: bundling related data under one name

r, g, b and opacity in sketch 04 were four separate variables that only ever made sense together — a colour isn't really "red" on its own, it's the combination of all four. An object is a way of grouping several related values under a single name, so they can be created, passed around and read as one thing instead of four. This sketch's col is the first object to appear in the series — built for us by a p5 function rather than written out by hand (that comes in sketch 06), but the underlying idea is the same: one name, several pieces of data bundled inside it.

Why objects exist at all: without them, r, g, b and opacity are four separate variables that happen to be related only by convention — nothing in the code says they belong together, and nothing stops one getting passed to a function without the others by mistake. An object makes that grouping real: col can be passed to fill() in one piece, stored, or handed to another function, and it's simply impossible to accidentally leave a piece behind. Rule of thumb: reach for an object when several values only ever make sense together and are usually read, changed or passed around as a set — if you find yourself always touching the same handful of variables side by side, that's the signal.

let, and why it's needed here

let col;
...
function setup() {
    ...
    col = color(255, 0, 100, 150);
}

col needs to be declared globally — both setup() (where it's built) and mousePressed() (where it's used in fill(col)) need to read it. But unlike sketch 04's consts, col can't be given its value at the point it's declared: its value comes from calling color(), and (see "How p5 works" below) color() can't actually be called yet at the top level, above setup(). So col is declared globally with no value at all — let col; — and only assigned once setup() starts running, where color() is safe to call.

This is exactly the situation let exists for: const requires a value at the moment it's declared, and here that's simply not possible yet. let allows a variable to be declared now and assigned later — and, unlike const, reassigned again afterwards if needed, though this sketch only ever assigns col once.
