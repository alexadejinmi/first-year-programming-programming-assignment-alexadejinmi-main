05 — A Colour Object

How p5 works

  • p5 functions that depend on p5's environment aren't callable until setup() starts running. Code written at the top level — outside any function, the way let col; is — runs immediately when the sketch loads, before p5 has finished setting itself up. Calling a function like color() from there would fail: it needs p5's environment to already exist, and that only happens once p5 starts calling setup(). This is the deeper reason col can't simply be written as let col = color(255, 0, 100, 150); at the top level — it's not that the value isn't needed yet, it's that calling color() that early would be an outright error. Every value that depends on a p5 function gets built inside setup() from here on, never at the top level. (Plain JavaScript values — like sketch 04's numbers — have no such restriction.)
  • color() builds a p5 colour object, which can be handed straight to fill() in place of four separate numbers — the first p5 function seen so far that hands back a richer object rather than a plain number.
  • The alpha (opacity) channel controls blending. Because the canvas is a persistent bitmap (sketch 01), a colour with reduced opacity doesn't replace what's underneath — it blends with it. A semi-transparent circle drawn twice in the same spot looks different from one drawn once, because the second draw blends with the first.
