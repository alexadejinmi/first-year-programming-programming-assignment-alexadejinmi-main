07 — A createBall() Function

Programming concepts

Function declarations with parameters and return

function createBall(x, y, d, c) {
    let b = {
        x: x,
        y: y,
        diameter: d,
        col: c
    };
    return b;
}

createBall is a function declaration with parameters — x, y, d, c — names listed in parentheses that stand for whatever values the function is called with. Calling createBall(320, 180, 150, col) runs the function with x bound to 320, y to 180, and so on. return b; hands a value back to wherever the function was called from — the caller can store it, exactly like color(...)'s result was stored in col back in sketch 05. A function with no return hands back nothing usable; setup()/draw()/mousePressed() never return anything, because p5 doesn't use a return value from them.

Parameters are local variables too

Like the col declared inside setup() in sketch 06, x, y, d and c exist only for the duration of one call to createBall() — but where col's value came from an assignment written inside the function, a parameter's value comes from whatever the caller passed as an argument. Every call to createBall() gets its own independent x, y, d, c, regardless of what any other call used.

A function as a factory

createBall()'s whole job is to build and hand back an object — a common pattern often called a factory function. Instead of writing the object literal directly in setup() (as sketch 06 did), setup() now just calls createBall(...) and stores whatever comes back. The object itself is built once, in one place, and can be built again with different arguments any time more balls are needed.

Passing arguments to customise what's built

Each argument to createBall() customises one part of the ball it builds — its position, size, or colour. This is the point of parameters: the same function produces a different object depending on what it's called with, rather than needing a separate, near-identical block of code for every ball.

Why functions exist at all: without createBall(), building a second or third ball would mean copying the whole { x: ..., y: ..., diameter: ..., col: ... } block again, with just the numbers changed — and fixing a mistake in that shape later would mean finding and fixing every copy. Wrapping it in a function means the object-building logic exists in exactly one place, and every call site just states what ball it wants, not how to build one. Rule of thumb: reach for a function when you're about to write the same (or near-identical) block of code more than once, or when a chunk of code does one clearly nameable job — naming and isolating it makes the rest of the sketch easier to read even the first time it's called, before a second copy ever comes up.
