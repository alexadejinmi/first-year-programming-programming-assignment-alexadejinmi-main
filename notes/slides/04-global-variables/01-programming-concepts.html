04 — Global Variables

Programming concepts

The assignment statement

diameter = 150;

The = sign is the assignment statement — it doesn't mean "equals" the way it does in maths; it means "store the value on the right into the name on the left". After this line runs, the name diameter refers to the value 150, until something assigns it a different value. Every sketch from here on relies on this — it's the mechanism behind every named value the rest of the series uses.

Declaring a variable with const

const diameter = 150;

const declares a name (creates it, so the rest of the code can use it) and, on the same line, assigns it a starting value — declaration and assignment combined into one statement. diameter is now a variable: a name that stands in for a value, usable anywhere later in the code instead of writing the value itself.

const as the default

const means the value can never be reassigned after this line — attempting diameter = 200; anywhere later would be an error (worth actually triggering, once, to see: the exercises below do exactly this). Every variable this sketch declares is const, because none of them ever need a new value after setup() finishes reading them. const is the sensible default for exactly that reason: a name that's guaranteed to always mean the same thing is easier to reason about than one that might change. (The alternative, let, is for a value that genuinely needs to change later — sketch 05 is the first place that's actually needed.)

Global scope

const diameter = 150;
...
function setup() { ... }
function mousePressed() { ... }
function keyPressed() { ... }

diameter is declared outside any function, at the top level of the file. A variable declared this way has global scope — it's visible to every function in the sketch, not just one. That's why mousePressed() and keyPressed() can both read diameter, bg, and the rest, despite none of them being declared inside either function.

Naming values instead of repeating literals

Sketch 01 called these magic numbers — literal values with no name to explain what they mean. Pulling each one out into a named const fixes both problems that come with magic numbers: the name (diameter, not 150) documents what the value is, and changing a value that's used in several places now means editing it in exactly one place, instead of hunting down every literal that happens to share the same number.
